## E2E 데모 시나리오 4단계 실행

로컬 서버에서 에이전트 채팅 API를 실호출하여 4단계 시나리오 검증:

1. **검색**: "김도현 찾아줘" → `search_applications` 호출, 동명이인 2명 안내
2. **조회**: "첫 번째 김도현 상세 보여줘" → `search + get_application` 2회 호출
3. **상태 변경**: "서류심사로 옮겨줘" → 후퇴 불가 안내 + 대안 제시
4. **이메일 초안**: "면접 안내 이메일 만들어줘" → `draft_email` → pending_action 반환

4단계 모두 정상 동작 확인.

## 프롬프트 튜닝 — ID 혼동 수정

E2E 데모에서 발견된 문제: 대화가 길어지면 에이전트가 `application_id`를 잘못 넣는 현상. `agent.v1.md`에 규칙 2줄 추가:

- application_id는 반드시 직전 도구 결과에서 확인된 ID를 사용
- "이 지원자" 같은 지시어는 가장 최근 조회한 지원자의 ID를 참조

**Before**: Step 4에서 `draft_email(application_id=1)` (엉뚱한 ID) → **After**: `draft_email(application_id=52)` (정확한 ID)

## 비용 실측 + STT 비용 로깅 추가

E2E 데모 4단계 실측 결과(Haiku 기준):

| 시나리오 | input | output | cost_usd |
|----------|-------|--------|----------|
| 검색 | 11,003 | 234 | $0.012 |
| 조회 | 17,249 | 349 | $0.019 |
| 상태 변경 | 5,801 | 184 | $0.007 |
| 이메일 초안 | 6,015 | 97 | $0.007 |
| **합계** | **40,068** | **864** | **$0.045** |

STT(Whisper)에 비용 로깅이 빠져 있었던 것을 발견, 추가 구현:

- `_estimate_stt_cost()` 함수 추가($0.006/분 × 오디오 길이)
- `transcribe()` 반환값에 `audio_duration_sec`, `cost_usd` 필드 추가
- 3개 기능(채팅·요약·STT) 전부 `cost_usd` 로깅 통일 완료

ADR-0011에 실측 데이터 기록, 후속 항목의 "실호출 대조" 완료 처리.
