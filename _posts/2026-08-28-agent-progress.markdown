### E2E 데모 시나리오 — 기본 4단계

로컬 서버에서 에이전트 채팅 API를 실호출하여 검증:

1. **검색**: "김도현 찾아줘" → 동명이인 2명 안내
2. **조회**: "첫 번째 김도현 상세 보여줘" → 프로필·단계 표시
3. **상태 변경**: "서류심사로 옮겨줘" → 후퇴 불가 안내
4. **이메일 초안**: "면접 안내 이메일 만들어줘" → pending_action 반환

### E2E 엣지 케이스 — 8개 시나리오 전부 PASS

| 시나리오 | 에이전트 동작 |
|----------|-------------|
| 검색 결과 0건 | "검색 결과가 없습니다" + 대안 제시 |
| 모호한 요청 (누구인지 안 밝힘) | 도구 호출 없이 명확화 요청 |
| 잘못된 단계명 ("합격") | 먼저 동명이인 확인 → 선택 유도 |
| 범위 밖 요청 (삭제) | "삭제 기능 미지원" + 가능한 기능 안내 |
| 공고 목록 조회 | list_postings 호출, 10개 표시 |
| 멀티턴 3단계 (검색→상세→이메일) | ID 추적 정확, draft_email 정상 |
| 특수문자 검색 (O'Brien) | 에러 없이 처리 |

### 프롬프트 튜닝 — ID 혼동 수정

`agent.v1.md`에 규칙 2줄 추가:
- application_id는 반드시 직전 도구 결과에서 확인된 ID를 사용
- "이 지원자"같은 지시어는 가장 최근 조회한 지원자의 ID를 참조

**Before**: Step 4에서 `draft_email(application_id=1)` (엉뚱한 ID)
**After**: Step 4에서 `draft_email(application_id=52)` (정확한 ID)
